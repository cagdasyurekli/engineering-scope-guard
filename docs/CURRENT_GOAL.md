# Evaluator-Environment-Locked Reasoning-Effort Experiment

## Goal

Establish a reproducible evaluator-environment identity and, only if every
prospective readiness gate passes, complete one exploratory comparison of
native `low` versus `medium` reasoning effort on externally executable
coding-task acceptance.

## Why now

The launch-surface-locked predecessor froze a 40-cell contract but stopped
before its first subject process because a newly resolved evaluator virtual
environment did not match the qualification environment's frozen Python
package-set identity. It produced zero subject or evaluator starts and no
treatment evidence. This separately authorized successor preserves that
terminal history and makes evaluator source, image, package, runner, and
task-specific identities explicit and reproducible before a new freeze.

## Success criteria

1. Revalidate canonical public `main`, required checks, ruleset, immutable
   v0.6 release, open CodeQL alerts, privacy boundary, and noreply identity.
2. Identify the predecessor mismatch to the actual drifting component and
   preserve the historical contract unchanged.
3. Implement one canonical layered evaluator-environment receipt covering
   evaluator source, immutable task image mapping, resolved package/toolchain
   state, runner identity, and legitimate task-specific inputs.
4. Normalize non-semantic host fields before hashing and deterministically test
   equality, material drift, task-specific variation, arm parity, and resume.
5. Reproduce the frozen semantic environment identity on at least two fresh
   evaluator worker instantiations and pass at most four outcome-blind gold or
   infrastructure preflight tasks.
6. Revalidate the existing 16 independent outcome-blind clusters, corrected
   monotonic Azure campaign clock, runtime/model/binary identity, treatment-only
   LOW/MEDIUM launch diff, subject quota, and non-contention with the separate
   Future Evaluator Reserve campaign.
7. If and only if every readiness gate passes, freeze ten primary clusters,
   four alternates, a balanced 40-cell schedule, and a 48-start absolute cap
   before subject cell 1.
8. Persist every pre-cell agent and evaluator sentinel and every attempt and
   evaluator receipt; permit at most two attempts only for prospectively
   defined `INFRASTRUCTURE_INVALID`, with no attempt 3 or manual rescue.
9. Analyze acceptance first at task/repository-cluster level, then work and
   adversarial falsification; select exactly one permitted scientific
   disposition and decide ESG-RR-002 separately.
10. Return experiment-owned Azure compute to pools `0`, jobs `0`, and active
    nodes `0` without modifying reserve-workstream resources. Complete the
    authorized PR/merge workflow and publish ESG-RR-002 only if scientifically
    justified and every publication gate passes.

## Model/reasoning plan

Use Sol-class high reasoning for experimental identity design, freeze/stop
decisions, analysis, falsification, and publication claims. Use deterministic
local tools for mechanical implementation and evidence processing. Subject
cells use one frozen runtime/model and vary only native `low` versus `medium`
reasoning effort.

## Stop conditions

Stop before subjects if the evaluator environment cannot be reproduced after
bounded prospective repairs, fresh workers differ, fewer than ten qualified
clusters remain, runtime/launch identity is unstable, subject quota is
insufficient, Azure contention cannot be avoided after all local work is done,
or scientific integrity is unresolved. Stop remaining cells on frozen agent or
evaluator identity drift. Also stop if a second/confirmatory experiment, PAYG or
new payment, spend above existing limits, repository reconstruction/deletion,
support contact, or external distribution would be required. Preserve exact
evidence and do not start another experiment.

and the separately owned Azure

program nevertheless reached its explicit pre-subject stop conditions and may
not be resumed or repaired under this authorization.
