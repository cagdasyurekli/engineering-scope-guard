# Evidence-Conditioned Final Scope Review v0.1 — Execution Interface Qualification

## Decision

**EXECUTION INTERFACE QUALIFIED — PROCEEDING UNDER EXISTING LIVE
AUTHORIZATION**

The smallest compatible interface reuses the qualified Pilot-v3 process,
isolation, credential, evaluator, timeout, checkpoint, and hash-chain
components. It adds one experiment-specific contract and one late-stage
delivery boundary; it does not create a generalized orchestrator or a second
review agent.

Qualification made zero Codex/provider subject calls, zero official evaluator
calls, zero experimental observations, and no execution ledger.

## Frozen execution identity

The canonical contract is
`experiment/evidence_conditioned_final_scope_review_v0_1_execution_contract.json`.
It binds:

- the exact 740 treatment bytes and SHA-256;
- the task-free design, selected exploratory pool, exact 32-cell schedule, and
  opaque confirmatory-reserve commitment;
- baseline as no intervention and treatment as the exact frozen bytes;
- `gpt-5.6-terra` with `medium` reasoning and Codex `0.151.0`;
- the pinned SWE-bench-Live MultiLang snapshot, evaluator, RepoLaunch, Docker,
  resource, and credential-isolation identities;
- the two-attempt maximum, four infrastructure-retry units, two operator-
  interruption units, one corrective round, and canonical Pilot-v3 timeout
  schema;
- the durable ledger, receipt, analysis, annotation, and retirement-gate
  executable components.

Any changed contract field, frozen artifact, component byte, runtime identity,
manifest, dataset file, evaluator boundary, or confirmation digest fails
closed.

## Late-stage treatment delivery

Both arms begin with the ordinary task bytes only. The initial Codex turn uses
a fresh repository, Codex home, credential copy, and session, with user config,
rules, hooks, MCP servers, plugins, and browser/network tools excluded.

Baseline ends that subject trajectory without any scope-review prompt.
Treatment activates only after the ordinary turn terminates successfully with
a durable session identity. The runner then uses one same-session
`codex exec resume` call whose standard input is exactly the frozen 740 bytes.
The activation checkpoint is fsynced after the ordinary-turn checkpoint and
before the treatment call. Prediction construction and official evaluation
occur only after that late-stage turn.

This mechanism makes the lifecycle auditable: the raw task trace precedes the
activation event, the exact treatment digest is recorded at activation, and
ordinary versus treatment/corrective trace references remain separate. A
pre-activation subject failure is a valid negative outcome with no treatment
exposure. The mechanism adds a subject turn to treatment and does not hide that
work from the frozen retirement gates.

## Deterministic qualification

The canonical dry-run resolves all 32 cells in frozen position order. All 32
begin at attempt 1; all 160 isolation roots are unique. Sixteen baseline plans
contain no intervention or late-stage resume. Sixteen treatment plans contain
the exact treatment digest and no ordinary-turn exposure. The dry-run writes no
ledger and invokes no subject or evaluator.

The qualification receipt records all 26 required checks as passed. Tests and
fault injection cover assignment drift, baseline leakage, early exposure,
duplicate completion, out-of-order and corrupted ledgers, attempt 3, retry and
interruption separation, operator relabeling, planned pauses, valid negative
outcomes, evaluator disposition/feedback combinations, contradictory evidence,
checkpoint and receipt ordering, missing evidence, cleanup across subject,
treatment, and evaluator failures, canonical timeout selection, and inert wrong
confirmation.

The terminal analysis code is also frozen before outcomes. It preserves the
required reporting order, task/repository cluster as the independent unit,
exact cluster bootstrap, leave-one-task-out sensitivity, unconditional quality
before work, jointly accepted paired mechanism evidence with its selection
caveat, all eleven retirement gates, and bounded exploratory claim limits.
Semantic mechanism annotations must cover observed treatment cells, use the
predeclared boolean schema, and cite evidence for every positive flag; absent
telemetry is never replaced with zero.

## Live boundary

Execution requires all of the following:

1. this qualification committed, green in CI and CodeQL, and squash-merged;
2. synchronized clean `main`;
3. a fresh strict preflight whose contract bytes match tracked `HEAD`;
4. the exact contract-derived live confirmation; and
5. the already-explicit chained authorization in the current request.

Confirmation and stabilized preflight checks occur before the state directory,
live marker, ledger, credential copy, task repository, or provider/evaluator
state can be created. If any gate fails, the required decision is
`EXECUTION INTERFACE NOT QUALIFIED — LIVE EXECUTION BLOCKED`.

Confirmatory identities and bodies remain inaccessible. Qualification does not
establish treatment efficacy, preserved quality, work reduction, monetary
savings, or any confirmatory claim.
